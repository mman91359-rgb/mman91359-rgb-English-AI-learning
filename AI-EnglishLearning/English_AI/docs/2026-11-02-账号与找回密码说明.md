## 2. 管理员设置指定密码

`PUT /admin/users/{id}/password`

```json
{ "password": "NewPass123" }
```

- 密码长度 6–72 位；BCrypt work factor 12。
- 受 `AdminAuthInterceptor` 保护。
- 审计动作 `USER_PASSWORD_SET`，只记录用户名，不记录密码。
- 原 `POST /admin/users/{id}/reset-password` 随机重置接口保留；前端两个入口并存。

## 3. 手机号找回密码（本地模拟）

`POST /user/forgot-password/reset`

```json
{ "phone": "13912345678", "code": "123456", "newPassword": "NewPass123" }
```

- 验证码固定 `123456`，仅用于本地演示。
- 生产 profile（`SPRING_PROFILES_ACTIVE=prod`）下服务端直接返回 400，不执行改密。
- 手机号在 `sys_user` 不是唯一索引，因此要求恰好匹配一个启用账号：
  - 0 条：400「手机号未绑定账号」
  - 多条：409「该手机号关联多个账号，请联系管理员」
  - 禁用账号：400「账号已被禁用」
- 网关白名单已包含 `/user/forgot-password`；前端 `request.ts` 也豁免该前缀的 401 自动跳转。

## 4. 后续接真实短信

保持 `/user/forgot-password/reset` 接口不变，替换 `PasswordResetService` 中的固定验证码校验为：

1. `POST /user/forgot-password/send-code` 生成随机验证码并发送短信；
2. 服务端用 Redis/数据库保存 code hash、过期时间、尝试次数；
3. reset 时校验 code hash、过期、单次消费、频率限制；
4. prod 禁止返回验证码，增加风控与审计。

当前未引入 Redis/短信依赖，符合项目“先 mock”的阶段目标。
