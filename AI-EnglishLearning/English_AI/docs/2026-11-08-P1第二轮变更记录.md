## 一、P1-2 体验与成本

### 1.1 错答反馈（带开关）

`accepted_answers` 非空但全部未命中时，提示由固定文案改为**直接给出正确答案**：

```
你的答案不符合本题的可接受答案，正确答案是：<correctAnswer>。
```

- 配置：`judgment.mismatch.reveal-answer`（默认 `true`，环境变量 `JUDGMENT_REVEAL_ANSWER`）
- 关闭后退回旧文案；**全程不调用 AI**
- 提交响应本来就返回 `correctAnswer`，不额外泄露

### 1.2 词库补全 8 个词

P0 遗留的 8 个词（`awareness / study / important / become / emergence / sustainable / substantiated / unequal`）不在词库中。处理方式：**脚本内置词干覆盖表**（不写回 `word_dictionary`）。

| 答案 | 词干/词性 | 新增变体 |
|---|---|---|
| study | study / v | studies, studied, studying |
| become | become / v（不规则） | became, becomes, becoming |
| substantiated | substantiate / v | substantiate, substantiates, substantiating |
| awareness / important / emergence / sustainable / unequal | 派生词或多音节形容词，无可加变形 | 仅原形 |

生成 `V1.0.25__patch_missing_word_forms.sql`：**3 行 UPDATE**，幂等守卫同 V1.0.24，**尚未执行**。

### 1.3 `matchedLevel` 常量类

新增 `common/src/main/java/com/english/ai/common/JudgmentLevel.java`：

| 常量 | 值 | 语义 |
|---|---|---|
| `LOCAL_MATCH` | 0 | 模块 2 连词成句本地比对 |
| `EXACT` | 1 | 正确答案 / accepted / L1 规则 / 选择题本地比对 |
| `SEMANTIC` | 2 | 错因路径 / 相似度 / 语义判对 |
| `AI_FEEDBACK` | 3 | AI 启发反馈 |

`JudgmentEngineImpl` 与 `ExerciseServiceImpl` 的字面量已全部替换，**取值不变**，前端 `L${matchedLevel}` 不受影响。

## 二、P1-3 性能与基建

### 2.1 `accepted_answers` 有界缓存（默认关闭）

- `ConcurrentHashMap<questionId, {values, expireAt}>`，无新增依赖
- 配置：`judgment.accepted-cache.enabled`（默认 `false`）、`ttl-seconds`（60）、`max-size`（2000）
- 超限时先清过期项，仍超限则整体清空，内存占用可预测
- 自学习写入 `accepted_answers` 后立即失效该题缓存
- 空集合同样缓存（配合失效，避免"无 accepted"被长期缓存）

### 2.2 判题埋点

新增 `JudgmentMetrics`（内存计数器 + 日志，无 actuator/micrometer 依赖）：

- 每次判题 `log.debug`：`qid / level / correct / elapsedMs / aiCalled`
- 每 100 次输出汇总：各层级命中数 + `aiRate`

### 2.3 Windows 构建脚本

新增 `scripts/mvn.cmd`，与 `scripts/mvn.sh` 能力对齐：

1. `JAVA_HOME` 含 `bin\javac.exe` 且主版本 ≥ 17 → 直接用
2. 否则依次尝试 `%ProgramFiles%\Java\jdk-21`、`jdk-17`、`C:\jdk-21`、`C:\jdk-17`
3. 都找不到则报错退出；找到后 `call mvn %*`

> 实现细节：`javac -version` 输出重定向到临时文件再读取，规避 `for /f` 在含空格路径下的引号解析问题；文件为 CRLF + 纯 ASCII，避免控制台代码页乱码。
