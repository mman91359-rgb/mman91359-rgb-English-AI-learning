### 判定基准

复用现有资产，不另写英语词法：

```
legit = correct_answer ∪ matchForms(lemma) ∪ acceptedForms(lemma)
      ∪ britishAmericanForms(lemma) ∪ {lemma}
```

`lemma` 来自 `question_info.answer_word`，缺失时用 `patch-accepted-top200.mjs` 的 `resolveLemma` 回退；
词性用 `generate-vocab-questions.mjs` 的 `categoryOf`，并用中文释义补第二词性（`complete` = `a.` + `vt.`）。

### 3.2 为什么 `COLLOCATION_CONFLICT` 有 922 条

这是「accepted 偏宽松」既定设计的直接体现：生成器把词条全部合法变形写进 accepted，具体题干往往只容得下一种。
例如 "We need to ___ the problem" 只接受 `analyze`，但 accepted 里有 `analyzes / analyzed / analyzing`。

不是错题，是**误判风险**。置信度 0.50、建议 `REVIEW`，是否收紧由人工按词批量判断。

### 3.3 规则调参记录（避免下轮重踩）

首版规则误报严重，逐条收紧后才有上面的结果：

| 问题 | 处理 |
|---|---|
| 词库 `pos` 只记主词性，`complete`/`abuse` 被判错 | 用中文释义补充词性集合，按每个词性分别生成合法集合 |
| 「空格 + 介词 → 动词」线索在 200 题抽样里误报 46 条（`capacity for`） | 删除该线索 |
| 「限定词/情态动词 + 空格 → 名词/动词」误伤 `an ___ ability`、`could ___ stay` | 删除这两条线索 |
| `to` 既是不定式也是介词（`filled to capacity`、`prefer A to B`、`from A to B`） | 增加介词搭配黑名单 + `-ed/-ing + to` 排除 |
| `so` 常作话语标记（`so ____ up!`） | 从程度副词线索中移除 |
| 伪形态只识别 `lemma+er`，漏掉 `kneer` / `poetrier` | 补去 e 加 r/st、y→i、CVC 双写 |

**原则**：线索没把握就跳过，宁可漏报不制造噪声。

## 四、模块2 为什么推迟

### 4.1 AI 不返回置信度

| 接口 | 实际返回 |
|---|---|
| `/ai/judge-acceptable`（L2.5 语义判对） | `acceptable` / `reason` / `altAnswer` |
| `/ai/judge-feedback`（L3 启发反馈） | `hint` / `errorType`（恒为 `UNKNOWN`）/ `suggestions` |

要拿到 `confidence`，必须改 `ai-service` 的 prompt 与解析，属于判题相关改造，需要单独评审。

### 4.2 exercise-service 没有异步能力

全模块无 `@EnableAsync` / `@Async` / `ExecutorService`，只有 `@EnableScheduling`。模块2 要"不阻塞主判题"，得自建一个有界线程池（单线程 + 有界队列 + 丢弃策略 + 日志），不能用现成组件。

### 4.3 启动模块2 的前置条件

1. 先用现有埋点观察 `aiRate`：`JudgmentMetrics` 每 100 次判题输出一行 `判题汇总 total=… level0..3=… aiRate=…%`；
2. 确认真实 AI 触发量后，再决定是否扩展 prompt 返回 `confidence`；
3. 扩展后走 `V1.0.29` 给 `judge_review_queue` 加 `ai_confidence` / `ai_result` / `judge_context`；
4. 阈值配置已预留（`judge.ai.review-enabled` / `review-threshold`），届时只需接线。

## 五、遗留与发现

1. **12 条伪形态待清理**：按「清单 → 人工确认白名单 → 单独一条迁移」三步走，删除式迁移需用 `JSON_REMOVE` / 重建数组，`WHERE` 以"包含该伪形态"为守卫保证幂等。
2. **922 条形态冲突待评估**：不是数据错误，是判题宽松度问题；若要收紧，需先定义"该题只接受哪种形态"的策略，属于产品决策。
3. **槽位线索覆盖率低**（266/4537 ≈ 5.9%）：没有 NLP 依赖，只能靠强线索；后续若引入词典的句法信息可提升。
4. **`ai-service/src/main/resources/application.yml:12`** 的 `model: ${DASHSCOPE_MODEL:qwen-plus}nt` 末尾多了字面量 `nt`，未设环境变量时模型名会是 `qwen-plusnt`——疑似配置笔误，本轮未修，属模块2 范围。
5. **`/ai/judge-feedback` 的 `errorType` 恒为 `UNKNOWN`**：ai-service 初始化后从未被 AI 返回值覆盖。不影响判分（exercise 侧只看 `hint`），但会让错因统计失真。
